# Remove K Digits
**LeetCode:** 402

**Pattern:** Monotonic Stack

**Difficulty:** Medium

**Importance:** ⭐⭐⭐⭐⭐ — Important for learning greedy decisions with a monotonic stack.

## Problem

Given a string `num` representing a non-negative integer and an integer `k`, remove exactly `k` digits so that the resulting number is the smallest possible number.

Return the resulting number as a string.

### Examples

```text
Input:
num = "1432219"
k = 3

Output:
"1219"
```

```text
Input:
num = "10200"
k = 1

Output:
"200"
```

```text
Input:
num = "10"
k = 2

Output:
"0"
```

---

## 🔹 Intuition

The goal is to make the number as small as possible.

When a smaller digit appears after a larger digit, the larger digit is hurting the number.

For example:

```text
1432219
  ↓
3 arrives after 4
```

Since:

```text
4 > 3
```

removing `4` makes the number smaller.

### Core Greedy Rule

> **When a smaller digit arrives, remove previous larger digits as long as removals are available.**

---

## 🔹 Why Monotonic Stack?

The stack maintains indices of digits that have survived so far.

When:

```text
current digit < stack-top digit
```

the stack-top digit should be removed because keeping it would produce a larger number.

This maintains an **increasing monotonic stack**.

Unlike the previous Monotonic Stack problems, here the stack is used for a **greedy removal decision**, not directly for finding the next greater/smaller element.

---

## 🔹 Approach

1. Traverse the number from left to right.
2. Store indices in a stack.
3. For every digit:

   * While the stack is not empty.
   * While the top digit is greater than the current digit.
   * While `k > 0`:

     * Remove the stack-top index.
     * Decrease `k`.
4. Push the current index.
5. If `k` is still greater than `0` after traversal, remove digits from the right.
6. Build the result by appending characters while popping the stack.
7. Reverse the result because the stack is processed from right to left.
8. Remove leading zeroes.
9. If nothing meaningful remains, return `"0"`.

---

## 🔹 C++ Solution

```cpp
class Solution {
public:
    string removeKdigits(string num, int k) {
        stack<int> st;
        string res = "";

        for (int i = 0; i < num.size(); i++) {
            while (!st.empty() && num[st.top()] > num[i] && k > 0) {
                st.pop();
                k--;
            }
            st.push(i);
        }

        while (k > 0) {
            st.pop();
            k--;
        }

        while (!st.empty()) {
            res += num[st.top()];
            st.pop();
        }

        reverse(res.begin(), res.end());

        int n = res.find_first_not_of('0');

        if (n == string::npos)
            res = "0";
        else
            return res.substr(n);

        return res;
    }
};
```

---

## 🔹 Complexity

**Time:** `O(n)`

Every index is pushed once and popped at most once.

Result construction uses `+=` followed by one `reverse()`, avoiding repeated string prepending.

**Space:** `O(n)`

The stack and result can each contain up to `n` elements.

---

## 🧠 Mistakes / Lessons

### 1. Correct algorithm but inefficient string construction

Initially used:

```cpp
res = num[st.top()] + res;
```

This repeatedly prepends to the string and can cause `O(n²)` string operations, resulting in **Memory Limit Exceeded**.

Correct approach:

```cpp
res += num[st.top()];
```

followed by:

```cpp
reverse(res.begin(), res.end());
```

### 2. Leading zeroes

After removal:

```text
"0200"
```

must become:

```text
"200"
```

If all remaining digits are zeroes:

```text
"0000"
```

return:

```text
"0"
```

### 3. Remaining `k`

If `k` remains after scanning the entire number, the number is increasing.

Example:

```text
12345
k = 2
```

Removing from the right:

```text
123
```

is smaller than removing from the left:

```text
345
```

Therefore:

> **If `k` remains after traversal, remove digits from the right.**

## 🔥 Pattern Recognition

Monotonic Stack can be used for more than finding the next greater/smaller element.

Look for situations where:

* A current element can make previous elements worse.
* A larger previous value should be removed when a smaller value arrives.
* We need to maintain an increasing/decreasing structure.
* A greedy decision can permanently remove an element.

### Core Mental Model

> **Maintain a monotonic structure and remove previous elements whenever the current element proves that they are no longer optimal.**
