# Largest Rectangle in Histogram

**LeetCode:** 84
**Pattern:** Monotonic Stack
**Difficulty:** Hard

## Problem

Given an array `heights` where each element represents the height of a histogram bar with width `1`, find the area of the largest rectangle that can be formed.

### Example

```text
Input:
[2, 1, 5, 6, 2, 3]

Output:
10
```

The maximum rectangle is formed using heights `5` and `6`:

```text
height = 5
width = 2
area = 10
```

---

## 🔹 Intuition

Think of each bar as a building.

For every building, ask:

> **How far can a rectangle of this height extend to the left and right before hitting a shorter building?**

The **first smaller building on the left** and the **first smaller building on the right** act as walls that stop the rectangle.

For a bar:

```text
Left boundary  = first smaller element on the left
Right boundary = first smaller element on the right
```

The boundaries themselves are **not included** in the rectangle.

Therefore:

```text
width = rightBoundary - leftBoundary - 1
area = height × width
```

### Important boundary rules

If there is no smaller element on the left:

```text
leftBoundary = -1
```

If there is no smaller element on the right:

```text
rightBoundary = n
```

---

## 🔹 Why Monotonic Stack?

While scanning from left to right, maintain indices of buildings that are still waiting to find their first smaller building on the right.

The stack maintains heights in **increasing order from bottom to top**.

When the current building is shorter than the stack top:

```text
current height < stack top height
```

the current building becomes the **right boundary** of the popped building.

After popping:

* The new stack top becomes the **left boundary**.
* If the stack becomes empty, left boundary is `-1`.

### Pop logic

```text
Current building is smaller
        ↓
Pop taller building
        ↓
Current index = Right boundary
        ↓
New stack top = Left boundary
        ↓
width = R - L - 1
        ↓
area = popped height × width
```

---

## 🔹 Approach

1. Scan the histogram from left to right.
2. Maintain a monotonic increasing stack containing indices.
3. For every current index:

   * While the current height is smaller than the height at the stack top:

     * Save the popped index.
     * Pop it.
     * Determine the left boundary from the new stack top.
     * Current index becomes the right boundary.
     * Calculate the rectangle area.
     * Update the maximum area.
4. Push the current index onto the stack.
5. After the array is completely processed, remaining bars have no smaller element on the right.
6. Use `n` as their right boundary and process the remaining stack.
7. Return the maximum area.

---

## 🔹 C++ Solution

```cpp
class Solution {
public:
    int largestRectangleArea(vector<int>& heights) {
        stack<int> st;
        int maxArea = 0;
        int R, L = -1;

        for (int i = 0; i < heights.size(); i++) {

            while (!st.empty() && heights[st.top()] > heights[i]) {

                int temp = st.top();
                st.pop();

                if (st.empty())
                    L = -1;
                else
                    L = st.top();

                R = i;

                int width = R - L - 1;
                int area = heights[temp] * width;

                maxArea = max(maxArea, area);
            }

            st.push(i);
        }

        while (!st.empty()) {

            int temp = st.top();
            st.pop();

            if (st.empty())
                L = -1;
            else
                L = st.top();

            R = heights.size();

            int width = R - L - 1;
            int area = heights[temp] * width;

            maxArea = max(maxArea, area);
        }

        return maxArea;
    }
};
```

---

## 🔹 Complexity

**Time:** `O(n)`

Every index is:

* pushed once
* popped at most once

Therefore, the total number of stack operations is `O(n)`.

**Space:** `O(n)`

The stack can contain up to `n` indices.

## 🧠 Mistakes / Lessons

### 1. Boundary handling — recurring weakness

Initially confused whether the boundary itself should be included.

**Correct thinking:**

> The first smaller building is a wall and is excluded from the rectangle.

```text
width = R - L - 1
```

---

### 2. First smaller vs smallest

Do not search for the smallest element.

The required boundary is:

> **The first smaller element encountered while moving left/right.**

The first smaller building immediately blocks the rectangle.

---

### 3. Nonexistent boundaries

If no smaller building exists:

```text
Left boundary  = -1
Right boundary = n
```

These are imaginary walls outside the array.

---

### 4. Remaining stack

After the main scan, some buildings may still be waiting.

This means:

> No smaller building exists to their right.

Therefore:

```text
R = n
```

and the remaining stack must also be processed.

---

## 🔥 Pattern Recognition

For Monotonic Stack problems, look for:

* Next greater element
* Next smaller element
* Previous greater element
* Previous smaller element
* Nearest element satisfying a greater/smaller condition
* Elements waiting for a future element to resolve them
* Range boundaries determined by the first smaller/greater element

### Core mental model

> **A stack stores unresolved elements. A future element resolves them when the required greater/smaller condition is satisfied.**

## 📌 Training Note

This problem reinforced the following personal weakness:

> **Boundary handling needs deliberate checking.**

Before calculating a range, explicitly identify:

```text
L = ?
R = ?
Are boundaries included?
```

Do not calculate the width intuitively.
